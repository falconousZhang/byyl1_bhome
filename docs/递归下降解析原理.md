# 递归下降语法分析原理与实现

> 对应实现文件：`src/parser_rd.py`

---

## 一、什么是递归下降分析

**递归下降**（Recursive Descent）是一种**自顶向下**的语法分析方法。

基本思想极为直接：**文法的每个非终结符对应一个解析函数**，函数之间相互递归调用，调用树与语法树同构。

与 LR(1) 的对比：

| | 递归下降 | LR(1) |
|--|---------|-------|
| 方向 | 自顶向下，预测 | 自底向上，归约 |
| 实现 | 手写函数，直观 | 需构造状态机 |
| 调试 | 易（调用栈即分析过程）| 难（状态编号抽象）|
| 表达能力 | LL 文法（无左递归）| 更强 |
| 左递归 | 不能直接处理 | 天然支持 |

递归下降最大的限制是**不能处理左递归**。例如 `add → add PLUS mul` 这条规则，如果直接写成函数调用，解析 `add` 时会立刻再调用 `add`，无限递归。本项目的解决方案见第五节。

## 二、Token 流的管理

整个解析器维护一个对输入序列的只读游标，通过四个基础操作驱动：

```python
class _Parser:
    def __init__(self, tokens):
        self._toks = [t for t in tokens if t.type != 'END']
        self._pos  = 0

    def _peek(self, off=0):
        """查看当前（或偏移 off 位）的 token 类型，不消费。"""
        i = self._pos + off
        return self._toks[i].type if i < len(self._toks) else 'END'

    def _cur(self):
        """返回当前 Token 对象。"""
        return self._toks[self._pos] if self._pos < len(self._toks) else None

    def _adv(self):
        """消费当前 token 并返回它。"""
        t = self._cur()
        if t: self._pos += 1
        return t

    def _expect(self, typ):
        """消费当前 token，若类型不符则记录错误。"""
        t = self._cur()
        if t and t.type == typ:
            self._pos += 1
            return t
        # 记录错误，返回 None（解析继续，不抛异常）
        self.errors.append({'msg': f"Expected '{typ}', got '{t.value if t else 'EOF'}'",
                            'line': t.line if t else 0, 'col': 0})
        return None
```

这四个方法是整个解析器的基础设施，其他所有解析函数都只通过它们与 token 流交互。

## 三、预测分析（Predictive Parsing）

递归下降的核心是"**向前看一个 token，决定走哪条规则**"。

### FIRST 集与分支选择

每个解析函数在开始时检查当前 token 类型，判断该走哪条产生式：

```python
def _type(self):
    p = self._peek()
    if p == 'I32':
        self._adv(); return TypeI32()           # type → I32
    if p == 'AMP':
        self._adv()
        if self._peek() == 'MUT':
            self._adv(); return TypeRef(True, self._type())   # type → & mut type
        return TypeRef(False, self._type())     # type → & type
    if p == 'LBRACKET':
        ...                                     # type → [ type ; NUM ]
    if p == 'LPAREN':
        ...                                     # type → ( type_list )
```

这里 `_peek()` 返回当前 token 类型，每个 `if` 分支对应一条产生式，分支条件恰好是该产生式 **FIRST 集**中的符号。

### 语句分派

语句的类型由第一个 token 完全确定，代码自然地写成一个大的 if-elif 链：

```python
def _stmt_or_tail(self):
    p = self._peek()

    if p == 'SEMI':    return EmptyStmt()                      # stmt → ;
    if p == 'RETURN':  return self._parse_return()             # stmt → return ...
    if p == 'LET':     return self._parse_let()                # stmt → let ...
    if p == 'WHILE':   return self._parse_while()              # stmt → while ...
    if p == 'FOR':     return self._for_stmt()                 # stmt → for ...
    if p == 'LOOP':    return self._loop_stmt_or_tail()        # stmt → loop ...
    if p == 'IF':      return self._if_stmt_or_tail()          # stmt → if ...
    if p == 'BREAK':   return self._parse_break()              # stmt → break ...
    if p == 'CONTINUE': ...                                    # stmt → continue ;

    # 其他情况：表达式开头（赋值语句或表达式语句）
    e = self._expr()
    if self._peek() == 'ASSIGN': ...    # stmt → expr = expr ;
    if self._peek() == 'SEMI':   ...    # stmt → expr ;
    return ('__tail__', e)              # 尾表达式（见第六节）
```

## 四、函数的递归结构

解析函数之间的调用关系与文法的推导关系完全对应。

### 程序入口

```
parse_program()
  └─ _func()            # 每个 fn 声明
       ├─ _param_list() # 参数列表
       │    └─ _param() # 每个参数
       │         └─ _type()
       └─ _block()      # 函数体
            └─ _stmt_or_tail()  # 每条语句
                 └─ _expr()     # 表达式
```

### 示例：解析函数声明

```python
def _func(self):
    fn   = self._expect('FN')       # 消费 fn 关键字
    nm   = self._expect('IDENT')    # 消费函数名
    name = nm.value if nm else ''
    self._expect('LPAREN')
    params = self._param_list()     # 递归解析参数列表
    self._expect('RPAREN')
    ret = None
    if self._peek() == 'ARROW':     # 可选的返回类型
        self._adv()
        ret = self._type()          # 递归解析类型
    body = self._block()            # 递归解析函数体
    return FunctionDecl(name, params, ret, body, lineno=fn.line)
```

代码的结构与产生式 `func_decl → FN IDENT LPAREN param_list RPAREN [ARROW type] func_body` 一一对应。

## 五、Pratt 解析（优先级爬升）

直接用递归函数处理二元运算有一个根本困难：左结合的左递归。

`add → add PLUS mul` 用函数实现会无限递归。常见的解决方案有两种：

1. **改写文法为右递归**：`add → mul (PLUS mul)*`——简单但难以实现左结合
2. **Pratt 解析（优先级爬升）**：用循环代替左递归，本项目采用此方案

### 算法

```python
# 优先级表
_PREC = {
    'EQ': 1, 'NEQ': 1,
    'LT': 2, 'GT': 2, 'LEQ': 2, 'GEQ': 2,
    'PLUS': 3, 'MINUS': 3,
    'STAR': 4, 'SLASH': 4,
}
_OP = {'PLUS':'+', 'MINUS':'-', 'STAR':'*', 'SLASH':'/',
       'EQ':'==', 'NEQ':'!=', 'LT':'<', 'GT':'>', 'LEQ':'<=', 'GEQ':'>='}

def _expr(self, min_prec=0):
    left = self._unary()            # 先解析一个一元表达式作为左操作数
    while True:
        p = self._peek()
        if p not in self._PREC or self._PREC[p] <= min_prec:
            break                   # 当前运算符优先级不够，停止
        op_tok = self._adv()        # 消费运算符
        # 右操作数：递归调用，传入当前优先级
        # 使用相同优先级（而非 +1）实现左结合
        right = self._expr(self._PREC[op_tok.type])
        left  = BinaryOp(self._OP[op_tok.type], left, right, lineno=op_tok.line)
    return left
```

### 优先级爬升的工作原理

以 `1 + 2 * 3` 为例，调用 `_expr(0)`：

```
_expr(0):
  left = _unary() → NumLit(1)
  peek = PLUS, PREC[PLUS]=3 > 0, 继续
  消费 PLUS
  right = _expr(3):          ← 传入 PREC[PLUS]=3
    left = _unary() → NumLit(2)
    peek = STAR, PREC[STAR]=4 > 3, 继续
    消费 STAR
    right = _expr(4):        ← 传入 PREC[STAR]=4
      left = _unary() → NumLit(3)
      peek = $, 不在 PREC 中，退出
      return NumLit(3)
    left = BinOp(*, 2, 3)
    peek = $, 不在 PREC 中，退出
    return BinOp(*, 2, 3)
  left = BinOp(+, 1, BinOp(*, 2, 3))   ← 正确：乘法优先
  peek = $，退出
  return BinOp(+, 1, BinOp(*, 2, 3))
```

**左结合的关键**：递归时传入的 `min_prec` 等于当前运算符的优先级（而非 `+1`）。

这样，当下一个运算符优先级**相等**时，条件 `PREC[p] <= min_prec` 为真，循环退出，右操作数不继续消费，从而实现左结合：

```
2 - 1 - 1 解析为 (2-1)-1，而不是 2-(1-1)
```

## 六、语句上下文 vs 表达式上下文

Rust 语言的一个特殊之处：**代码块最后可以不加分号，其值作为整个块的返回值**。

```rust
fn foo() -> i32 {
    let x = 1;
    x + 1       // ← 没有分号，这是块的"尾表达式"，即返回值
}
```

### _stmt_or_tail 的返回值类型

`_stmt_or_tail` 有两种可能的返回值：
- 普通语句节点：`LetStmt`, `ExprStmt`, `IfStmt` 等
- 特殊标记元组：`('__tail__', expr)`

`_block` 通过检查返回值类型来区分：

```python
def _block(self):
    self._expect('LBRACE')
    stmts, tail = [], None
    while self._peek() not in ('RBRACE', 'END'):
        r = self._stmt_or_tail()
        if r is None: break
        if isinstance(r, tuple) and r[0] == '__tail__':
            tail = r[1]; break      # 尾表达式，停止收集语句
        stmts.append(r)
    self._expect('RBRACE')
    return Block(stmts, tail)       # tail 可以是 None 或一个 expr
```

### if / loop 的二义性问题

在语句上下文中，`if` 和 `loop` 永远产生**语句节点**（`IfStmt`、`LoopStmt`），而不是表达式节点（`IfExpr`、`LoopExpr`）。

这与 PLY LALR(1) 的行为一致——PLY 的归约-归约冲突由"先出现的规则优先"解决，`stmt → if_stmt` 先于 `expr → IF ...`，所以在语句上下文中永远归约为 IfStmt。

```python
def _if_stmt_or_tail(self):
    # ... 解析 IF expr block [ELSE ...]
    # 关键：无论是否后面跟着 }，都返回 IfStmt，绝不返回 ('__tail__', IfExpr)
    return IfStmt(cond, then, elseif_clauses, else_block, lineno=ln)

def _loop_stmt_or_tail(self):
    # 同理，永远返回 LoopStmt
    return LoopStmt(body, lineno=t.line)
```

只有在显式的**表达式上下文**（如赋值右侧、函数参数、`let x = ...`）中，`_primary()` 才会调用 `_if_expr()` 或创建 `LoopExpr`：

```python
def _primary(self):
    ...
    if p == 'IF':
        return self._if_expr()          # ← 表达式上下文，必须有 else
    if p == 'LOOP':
        t2 = self._adv()
        return LoopExpr(self._block(), lineno=t2.line)
```

## 七、一元运算和后缀运算

### 一元运算（_unary）

```python
def _unary(self):
    p = self._peek()
    if p == 'MINUS':
        t = self._adv()
        return UnaryOp('-', self._unary(), lineno=t.line)   # 右结合递归
    if p == 'STAR':
        t = self._adv()
        return UnaryOp('*', self._unary(), lineno=t.line)   # 解引用
    if p == 'AMP':
        t = self._adv()
        if self._peek() == 'MUT':
            self._adv()
            return UnaryOp('&mut', self._unary(), lineno=t.line)
        return UnaryOp('&', self._unary(), lineno=t.line)
    return self._postfix()
```

一元运算是**右结合**的（`--x` 解析为 `-(-(x))`），因此直接递归调用自身而不传递优先级。

### 后缀运算（_postfix）

```python
def _postfix(self):
    node = self._primary()          # 先解析基元
    while True:
        if self._peek() == 'LBRACKET':      # node[idx]
            t   = self._adv()
            idx = self._expr()
            self._expect('RBRACKET')
            node = IndexExpr(node, idx, lineno=t.line)
        elif self._peek() == 'DOT':         # node.field
            t = self._adv()
            n = self._expect('NUM')
            node = TupleFieldExpr(node, int(n.value), lineno=t.line)
        else:
            break
    return node
```

后缀运算用**循环**实现，天然支持连续后缀：`a[0][1].2`。

## 八、括号与元组的区分

`(expr)` 是加括号的表达式，`(a, b)` 是元组，`()` 是空元组。三种写法都以 `LPAREN` 开头，需要区分：

```python
def _paren_or_tuple(self):
    t  = self._adv()         # 消费 LPAREN
    ln = t.line

    if self._peek() == 'RPAREN':            # () → 空元组
        self._adv()
        return TupleExpr([], lineno=ln)

    first = self._expr()                    # 解析第一个表达式

    if self._peek() == 'RPAREN':            # (expr) → 加括号的表达式
        self._adv()
        return first                        # 直接返回，不包装为元组

    # 否则是元组：(expr, ...)
    elems = [first]
    while self._peek() == 'COMMA':
        self._adv()
        if self._peek() == 'RPAREN': break  # 允许尾逗号 (a,)
        elems.append(self._expr())
    self._expect('RPAREN')
    return TupleExpr(elems, lineno=ln)
```

**判断逻辑**：先尝试解析一个 expr，再看下一个 token：
- `RPAREN` → 不是元组，直接返回 expr
- `COMMA` → 是元组，继续收集元素

这种"先走一步再判断"的思路在递归下降中很常见，因为在读完第一个 expr 之前，无法确定是哪种情况。

## 九、else-if 链的展开

文法中 `if_stmt → IF expr block ELSE if_stmt` 是右递归的，自然地产生右结合的树。但 AST 的 `IfStmt` 节点设计为扁平的 `elseif_clauses` 列表，需要在解析时把嵌套结构展开：

```python
def _if_stmt_or_tail(self):
    t    = self._adv()       # 消费 IF
    cond = self._expr()
    then = self._block()

    if self._peek() != 'ELSE':
        return IfStmt(cond, then, [], None, lineno=t.line)

    self._adv()  # 消费 ELSE

    if self._peek() == 'IF':
        # else if：递归解析内层 if，再把它的 elseif_clauses 合并到外层
        inner = self._if_stmt_or_tail()
        return IfStmt(cond, then,
                      [(inner.cond, inner.then_block)] + inner.elseif_clauses,
                      inner.else_block,
                      lineno=t.line)

    else_block = self._block()
    return IfStmt(cond, then, [], else_block, lineno=t.line)
```

`if a {} else if b {} else if c {} else {}`
最终产生：`IfStmt(a, {}, [(b,{}), (c,{})], {})`——一个扁平列表，便于代码生成遍历。

## 十、错误恢复策略

本实现采用**不抛异常**的容错策略：遇到错误时记录到 `self.errors` 列表，然后尽量继续解析。

```python
def _expect(self, typ):
    t = self._cur()
    if t and t.type == typ:
        self._pos += 1
        return t
    # 错误：记录，返回 None，调用方需处理 None
    self.errors.append({
        'msg':  f"Expected '{typ}', got '{t.value if t else 'EOF'}'",
        'line': t.line if t else 0,
        'col':  getattr(t, 'col', 0) if t else 0,
    })
    return None
```

调用方通过检查返回值是否为 `None` 来处理缺失的 token：

```python
nm   = self._expect('IDENT')
name = nm.value if nm else ''    # ← 安全处理
```

最终，`parse_rd` 函数检查 `self.errors`，若有错误返回 `(None, errors)`：

```python
def parse_rd(token_list):
    p   = _Parser(token_list)
    ast = p.parse_program()
    if p.errors:
        return None, p.errors
    return ast, []
```

## 十一、与 LR(1) 的完整对比

| 维度 | 递归下降 (RD) | LR(1) |
|------|------------|-------|
| **代码行数** | ~400 行 | ~820 行 |
| **分析方向** | 自顶向下 | 自底向上 |
| **左递归** | 不支持（Pratt 绕过）| 天然支持 |
| **调试方式** | 直接看调用栈 | 查状态机状态 |
| **错误信息** | 精确（知道期望什么）| 较粗（状态编号）|
| **表达能力** | LL(1)（加 Pratt 后接近 LR）| LR(1)（最强）|
| **启动时间** | 即时 | 首次 0.3s（之后缓存）|
| **修改文法** | 改函数即可 | 需重新构造状态机 |

两种方法在本项目的 **44 个样例上输出完全相同的 AST 和 IR**，可通过 `test_rd.py` 验证。
